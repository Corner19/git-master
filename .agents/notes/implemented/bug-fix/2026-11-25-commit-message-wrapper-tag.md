# Agent Note: 模型照抄提示词里的 `<commit-message>` 包裹，标题变成标签本身

Status: implemented

## 问题

用户用 DeepSeek 生成提交信息，拿到的草稿是这样：

```
<commit-message>

feat(诊断): 规则包新增推荐检查目录

- 规则包可含 0–200 条 investigations，属不可变内容并计入 contentHash
- 规则详情接口原样返回，缺省时输出空数组以兼容旧包
</commit-message>
```

标签不是模型乱加的，是**提示词自己要来的**：`buildSystemPrompt` 为了让"subject 与 body 之间
必须有空行"这条规则落地，给了一个填好的示例，并且为了标出消息的起止，把示例整个包在
`<commit-message>…</commit-message>` 里（见
[提交信息生成：把语言从"推断"改成参数](../architecture/2026-09-11-commit-message-prompt.md) 的"格式不能靠提示词保证"一节）。
指令遵循度高的模型（如 DeepSeek）会把示例形状连同包裹一起复制。

而模型输出之后那层确定性重整只剥两样东西——``` 围栏与 `Commit message:` 前缀——
**没有剥这个包裹**。后果不是"多一行噪音"，而是整条消息错位：
第一行 `<commit-message>` 被当成 subject，真正的标题下沉成正文第一段，`</commit-message>`
挂在正文末尾。消息框里看着像有内容，提交后 `git log --oneline` 显示的标题是 `<commit-message>`
——与"缺空行"同一类看不见的失败，只是成因相反：那次是分隔符没写，这次是包裹没去掉。

## 决策

在 `tidyCommitMessage()` 里加 `unwrapCommitMessage()`，与剥围栏、剥 `Commit message:` 前缀
并列，**不动提示词**：

- 整体包裹（`<commit-message>…</commit-message>`，含标签后另有空行、大小写混写）→ 取内部文本；
- 只有一侧标签或标签与内容混排 → 按行丢弃**独占一行**的标签行，其余原样保留。

两个边界都是刻意的：

- **提示词不改。** 标签在示例里提供了 `no preamble` 管不住的那条边界（消息从哪里开始、
  到哪里结束），删掉它换来的是一堆"好的，这是提交信息："。既然"机械可判的格式由代码强制"
  已经是这个子系统的既定决策，包裹就该在这一层剥掉，而不是靠模型自觉不抄。
- **只丢独占一行的标签。** 正文里合法提到 `<commit-message>`（比如这条修复自己的提交信息、
  或本笔记）不能被吃掉，所以判据是整行只有标签，不是"包含标签"。

顺序也有要求：先剥围栏、再剥包裹，因为 ```markdown 里套标签是最常见的双层形式。

## Alternatives considered

- **把示例改成不带标签的纯文本**：会让模型失去消息起止的边界，换来 preamble 与"这是提交
  信息："一类前缀（`tidyCommitMessage` 早就在剥这种前缀，说明它常发生）。等于把一个问题换成
  另一个已知问题。否决。
- **把示例写成代码围栏**：system 文本明确禁止模型输出围栏（`no markdown code fences`），
  示例自己带围栏等于教它违规。
- **只在提示词里补一句"不要输出这些标签"**：这条子系统的既有结论是提示词只能提高概率；
  而且"示例有标签、文字说不要标签"本身是自相矛盾的信号，模型会挑一个。代码兜底是确定性的。
- **让视图层（`src/commit-view.js`）在写进消息框前再整理一次**：格式是提交信息的属性，不是
  某个视图的属性；`main.js` 是所有调用都经过的唯一位置，两个视图自动一致。
- **把标签行连同其后的空行一起删**：会在"标签 + 空行 + 正文"（用户实际遇到的形式）里留下
  前导空行，还得再 trim 一次；整体正则直接覆盖这种形式。

## 后果

- 收益：模型无论抄不抄包裹，用户拿到的都是真正的标题在第一行、正文在空行之后的提交信息；
  DeepSeek 这类照抄示例的模型不再是缺陷触发条件。
- 收益：判据可被不变量断言——包裹、单侧标签、围栏内套标签、大小写混写、正文合法提及标签、
  已正确草稿的幂等，六类形状一次覆盖（9/9，见验证）。
- 代价：`tidyCommitMessage` 多一层正则；`</?commit-message>` 独占一行时一定被丢弃，若将来
  真的需要在正文里单独写一行这个标签，只能靠缩进绕开（可接受，提交信息正文里不会这么写）。
- 验证：`node --check main.js` 通过；`node tools/harness.mjs` 222/222（含 agent-note 门禁）。
- 遗留：模型若在标签**之前**写 preamble（"好的，这是提交信息："），`unwrapCommitMessage` 的
  整体匹配不成立，会走按行剥标签的分支，preamble 就留在 subject 里。本次未处理——用户报告的
  形状里没有它，且它与"缺空行""标签未剥"不同，不是提示词示例直接教出来的。
