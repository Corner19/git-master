# Agent Note: 空闲时整块重画导致提交/日志面板每几秒抖一下

Status: implemented

## 问题

用户反馈：Git 工具窗口"什么都不做它也一直抽，每几秒一次，水平和垂直都抖"，集中在
**变更（提交视图）**面板，出现抖动的工作区带子模块。

用真实桥接复现（`views/git.html` + `main.js` 直连，见下方验证）：一个 63 提交、107 个
改动（含一个脏子模块）的仓库，页面完全静止的情况下，每 3.5 秒发生 **4 次全量重建**，
累计约 **2,500 个节点**被拆掉重建：

1. `refreshInner()` 开头的 `paintAll()`（用上一次的子模块状态画根仓状态）；
2. `state.subLoading = true` 之后的 `paintChangesHeader()` —— 变更标题栏的"…"闪一下
   （实测标题从 `变更107` → `变更107…` → `变更107`，约 120ms）；
3. 子模块状态取回后的 `paintAll()`；
4. `loadDiff()` 里的 `paintDiff()`。

触发源是 `PIG.startAutoRefresh` 的静默心跳（`HEARTBEAT_MS = 3500`，见 `src/common.js`）。
心跳本身是对的（回归"从编辑器/终端回来时列表是新的"），错的是**心跳发现仓库没变还是把
每一块都重画一遍**：`paintAll()` 无条件 `PIG.clear()` 后重建变更树、diff、提交区、工具栏。
重建同一份内容虽然不改变几何尺寸，但会让鼠标下的行丢失 hover、把 diff 的滚动与选区一起
丢掉，并在中间态（根仓状态已新、子模块状态还是旧的那一帧）露出与最终结果不一致的行数——
带子模块、行数接近面板高度时，这一帧的行数差就是一个可见的上下跳。日志面板同病：
`loadLog()/loadRefs()` 每次心跳重画 846 个节点。

## 决策

给"重画"加上幂等闸门：**画之前先算一份它要读的状态指纹，指纹没变就直接返回**。

- `src/commit-view.js`
  - 新增 `paintSignature()`（仓库状态、子模块、选中、筛选、视图选项、提交草稿开关、
    `collapsed` 集合等），`lastPaintSignature` 记住上次画过的值；`refreshInner()` 结尾
    `paintAll()` 只在指纹变化时执行。切换仓库时（`forgoRepositoryState()`）把它清空，
    保证换仓必画。
  - 子模块状态改为**画之前**取（`git/submodule-statuses` 先于 `paintAll()`），于是
    `state.subLoading` 与"…"提示整体删除——没有半成品可提示了。首次挂载仍先画一次
    （`lastPaintSignature === null`），避免多子模块仓库首屏空白等待。
  - `loadDiff()` 用 `paintedDiffKey`（选中文件 + 模式 + 忽略空白 + diff 文本）挡住重复
    重建：心跳仍然会重新拉 diff（文件可能被编辑而 Git 状态不变），内容一样则不重画。
- `src/git-view.js`：`paintList()` / `paintBranches()` / `paintDetail()` 各带一份指纹
  （提交 hash 列表、分支/标签/远端/储藏、选中与 changedFiles 等）。列表与储藏行显示
  相对时间，所以指纹里带一个**分钟桶**（`minuteBucket()`）：相对时间最多每分钟刷新一次，
  而不是每次心跳。
- 两处 `pig:appearance` 监听在重画前清空指纹（主题/语言切换会改写所有文案，否则闸门会
  把旧语言留在屏上）。

## 验证

- 复现台架（临时脚本，不入库）：`main.js` 起 `onPanelInvoke` 桥接 + 静态页，
  headless Chrome 在 900×700 打开带子模块的真实仓库。
  - 改动前：12 秒内 4 次 × ~830 节点重建/心跳，标题"…"闪烁。
  - 改动后：同一页面 **14 秒内零重建**（提交面板与日志面板都不动）。
- 功能未被闸门冻住（同一台架）：
  - 点另一个改动文件 → diff 内容整体变化（`@@ -0,0 +1 @@`）；
  - 勾选暂存 → 分组从 `[未暂存62, 未纳入版本控制的文件46]` 变为
    `[已暂存1, 未暂存62, 未纳入版本控制的文件45]`；
  - 外部新建未跟踪文件 → 一次心跳后标题 `变更107` → `变更108`，行数 112 → 113；
  - 点第 5 条日志 → 选中行与详情哈希同时变；搜索框输入 → 列表 63 行 → 11 行；
  - 外部 `git commit` + 新建分支 → 一次心跳后行数 63 → 64，分支面板出现新分支。
- `node tools/build.mjs` 重生成三产物，`node --check` 通过；
  `node tools/notes.mjs`、`node tools/harness.mjs`、`tools/commit-layout-regression.mjs`、
  `tools/git-multi-regression.mjs`、`tools/daily-summary-regression.mjs`、
  `tools/icon-consistency-regression.mjs` 全通过。

## Alternatives considered

- **拉长心跳间隔 / 关掉心跳**：心跳解决的是真问题（外部改动后列表是旧的）；拉长只是把
  抖动变慢，且让"从终端回来看到旧列表"的窗口变大。否决。
- **只做滚动位置与选区的保存/恢复**：重建本身没有了，但 hover、diff 重排、中间态行数差
  都还在；而且实测（清单在一次任务内 clear+append）滚动位置本来就不会丢——症状不是它。
- **给 `scrollbar-gutter: stable`**：能消掉滚动条出现/消失带来的 10px 位移，但实测静态
  尺寸下滚动条并不反复出现，抖动来自重建频率。属于针对错因的修补。
- **把指纹塞进每个 painter（含工具栏）**：工具栏一次心跳只重建 ~59 个节点，且
  `state.syncing` 等瞬时态最容易漏进指纹导致按钮状态过期。收益小、风险大，先不动。

## 后果

- 收益：仓库没变时面板完全静止——不再每 3.5 秒拆建 2,500 个节点，鼠标下的行不再闪，
  diff 不再被无谓重建；渲染进程在"什么都不做"时也从每 3.5 秒的整树 churn 变成零。
- 代价：指纹是"重画依赖哪些状态"的显式清单，新增一个被 painter 读取的字段时要记得加进
  指纹，否则改动后不重画。日志的相对时间从"每次心跳刷新"降为"每分钟刷新"。
- 遗留：两个工具栏仍每次心跳重建（~59 节点，无可视抖动），未纳入本次闸门。
